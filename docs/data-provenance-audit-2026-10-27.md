# Public data provenance audit — 27 October 2026

Scope: landing page, Developers page, Students/Community/College screens, Community News, weather, seasons, Ask Ace examples and scenario display. This is a read-only audit of the checked-out `main` source and sampled public API responses around 11:55–12:02 UTC. Values change continuously. An API endpoint returning a value does not establish that the value was measured or correctly sourced.

## Verdict

The site cannot yet defend every displayed number as live or independently sourced. It has real ACE telemetry, real historical bins, OpenWeather observations, approved news feeds and a regional grid API. It also has fixed conversion factors, scripted stories, a manually seeded turbine power curve, assumptions presented as impact, stale-data gaps, and an empty seasonal year. Fixed engineering facts should come from cited documents and versioned configuration; they do not need to change through an API every second. The UI must distinguish **measured**, **derived from a stated method**, **historical estimate**, **static sourced fact**, and **illustration**.

`shared/constants.js` names `PROJECT_OVERVIEW.md`, `DATA_DICTIONARY.md`, `API_REFERENCE.md` and an exploratory analysis as sources, but those documents are not present in this checkout. Their absence is a provenance gap for exact values such as 4,245 kW and the chosen impact factors; an assertion in a code comment is not a verifiable citation.

| `/api/stories` | Generated caption variants, dated 27 Oct | Text is generated from fixed fact prompts and live placeholders. The validator forbids digits but cannot independently verify qualitative statements. |

The separate database audit confirmed `/api/health` reported PostgreSQL and Redis healthy, with recent ACE history syncs succeeding. Public `/api/datasets` reported SCADA/daily coverage **21 July–27 October 2026**, minute/weather coverage **14–27 October 2026**, and status coverage **19 July–26 October 2026**. The [upstream ACE status window](https://ace-api.duckdns.org/v1/status) begins 21 July 2026 for 10-minute rows, and the [current Zenodo release](https://zenodo.org/records/23114177) contains 2026 data, not a 2025 file. Live state and news use Redis; history, seasonal aggregates and dataset exports use PostgreSQL/Timescale; grid calls its external API with an in-process cache. Database health alone cannot certify all data streams.

Quality gates are not equivalent to engineering validation: ingestion rejects malformed/implausible SCADA pages using broad bounds (including up to 6,500 kW), while empirical power-curve bins include downtime, curtailment and negative parasitic power. Records report a 4,357 kW 10-minute peak even though configured rated output is 4,245 kW; it may be an observed field maximum, but has not been independently quality checked as continuous power. A sampled live rotor reading was 13.8 rpm; the generic OEM sheet gives 13.2 rpm as its 4,200 kW variant range, so ACE's installed settings or sensor definitions need confirmation before using that generic range as a limit. The records total of about 2.61 million kWh covers only July–October 2026 and must not be compared as though it were the lifetime meter of about 31.48 million kWh. Daily summaries prefer meter differences when checks pass and otherwise estimate from power; current-day coverage was partial.

## Highest-priority corrections before a defensible presentation

1. Hide or explicitly disable the empty Seasons comparison; verify/archive-backfill 2025 or use a clearly dated period with actual coverage.
2. Apply age checks to **each** turbine, weather, grid and history observation. Correct the ~51-second ACE/source clock lead before using `liveAt` as proof of freshness. Show “last known” beside every affected number, not only in the badge.
3. Remove “manufacturer reference” from the seeded curve until its exact points can be matched to an OEM publication for this installed variant. Keep empirical bins separate with sample counts and uncertainty.
4. Replace unqualified “CO₂ avoided/saved” and “homes powered” with defensible **estimated equivalents** and visible factor, year and method. Do not treat grid average intensity as marginal avoided emissions.
5. Correct the commissioning row and capacity-factor start date from ACE’s May 2023 record; reconcile 89/90/92m reference heights and the illustrative foundation depth.
6. Label scripted scenes and demo chat as examples. Keep unsupported causal claims (especially “every kWh displaces gas”) out of factual captions.
7. Publish a per-metric source register with observation timestamp, unit, calculation version, licence/attribution and UI label; verify public API and UI against it before a live presentation.
